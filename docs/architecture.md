# 多社区架构约定

组织层级：城市 → 区域 → 社区 → 集市 → 摊位 → 商品。层级数据配置化，商品归属由数据库外键约束。

## 隔离原则
- 每条社区业务记录必须有 community_id；平台级任务可为空但必须 scope=platform。
- 普通列表 API 必须显式接收 communityId，并在服务端过滤。
- 跨社区搜索仅查询 communities.status=open，结果必须携带来源社区名称与位置文本。
- 距离仅在双方经纬度可信且用户授权位置可用时计算；否则不展示距离。
- 中关村状态为 coming_soon，不得进入公开商品搜索集合。

## Agent 分工
平台级：总调度、情报收集、智能匹配、消息中转；社区级：社区运营员。平台 Agent 负责编排和跨社区检索，社区 Agent 仅能读写其授权 community_id。

## 推荐模式
local：当前社区；nearby：当前社区优先，再按后台配置的邻近社区列表；all：所有开放社区。不得将未经证实的直线距离伪装为实际距离。

## MVP 边界
当前 UI 使用 src/data/market.ts 内显式演示数据；尚未接入认证、交易 API、消息持久化和真实 LLM。生产环境必须以服务端社区权限和数据库约束实现隔离，不能依赖前端过滤。
